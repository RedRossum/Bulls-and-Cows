# Архитектурная документация: Bulls and Cows

В данном файле описаны ключевые архитектурные решения, структуры данных, алгоритмы и их вычислительная сложность (Big O), а также принципы чистого кода, примененные в проекте.

## Структуры данных и состояние игры

Все типы данных централизованно вынесены в файл `src/types/index.ts` и импортируются в логику с помощью синтаксиса `import type`. Архитектура ядра построена на принципах **чистого функционального программирования (FP)** без использования классов и мутаций.

## Анализ функций и вычислительная сложность (Big O)

### 1. `createDigitValidator(base)`
*   **Описание:** Каррированная фабрика валидаторов цифр. Принимает систему счисления и возвращает предикат проверки символа.
*   **Сложность:** **O(1)**
*   **Обоснование:** Поиск регулярного выражения в объекте-карте по ключу системы счисления происходит за константное время $O(1)$. Проверка входящего символа регулярным выражением (`RegExp.test`) для строки длиной в 1 символ также выполняется за константное время $O(1)$.

### 2. `isValidGuess(guess, length, base)`
*   **Описание:** Проверяет строку-попытку игрока на соответствие правилам (совпадение длины, валидность символов алфавита, отсутствие дубликатов).
*   **Сложность:** **O(N)**, где $N$ — длина строки `guess` (параметр `length`).
*   **Обоснование:**
    1. Перевод строки в массив через `.split('')` занимает $O(N)$ времени и памяти.
    2. Метод `.every()` обходит массив один раз, выполняя проверку $O(1)$ для каждого символа, что суммарно дает $O(N)$.
    3. Метод `.map()` для приведения к нижнему регистру обходит массив за $O(N)$.
    4. Создание структуры данных `Set` из массива обходит элементы за $O(N)$ и занимает $O(N)$ памяти.
       Все операции выполняются последовательно, поэтому общая временная и пространственная сложность линейно зависит от длины строки — $O(N)$.

### 3. `generateSecret(length, base, random)`
*   **Описание:** В соответствии с ТЗ, генерирует секретное число заданной длины из уникальных цфифр в выбранной системе счисления.
*   **Сложность:** **O(L * A)** в худшем случае, где $L$ — заданная длина секрета (`length`), а $A$ — размер алфавита системы счисления (`base.length`).
*   **Обоснование:** Рекурсия гарантированно выполняет $L$ успешных шагов для сбора всех цифр. На каждом шаге метод `acc.includes()` обходит массив аккумулятора (максимум $L$ операций), а создание нового массива через spread-оператор `[...acc]` копирует текущие элементы (до $L$ операций). В худшем случае, если генератор случайных чисел будет постоянно выдавать уже существующие цифры, количество повторных «холостых» перезапусков рекурсии зависит от размера алфавита $A$.

### 4. `evaluateGuess(secret, guess)`
*   **Описание:** Сравнивает попытку игрока с секретным числом и подсчитывает быков и коров. В соответствии с ТЗ, регистр букв для шестнадцатеричной системы не важен, а вся логика написана через методы массивов (`filter`) без ручных циклов.
*   **Сложность:** **O(N * M)** в общем случае, но так как длина строк всегда равна и ограничена ($N = M = \text{length}$), общая сложность сводится к **O(N²)**, где $N$ — длина секретного числа.
*   **Обоснование:**
    1. Приведение строк к нижнему регистру и создание массива символов через `.split('')` занимает $O(N)$.
    2. Подсчет быков через `.filter()` обходит массив за $O(N)$ шагов, выполняя сравнение по индексу за $O(1)$.
    3. Подсчет коров через `.filter()` также делает $O(N)$ шагов, но внутри каждого шага вызывается метод `secretLower.includes(char)`. Этот метод под капотом сканирует строку секрета, что занимает до $O(N)$ операций.
       В итоге последовательные вызовы дают $O(N) + O(N \cdot N) = O(N^2)$. При максимальной длине секрета 6 символов алгоритм работает мгновенно.

### 5. `countPossibleSecrets(length, base)`
*   **Описание:** В соответствии с ТЗ, вычисляет количество существующих различных секретных чисел (перестановок без повторений) для заданных длины и системы счисления. Реализована рекурсивно по заданной формуле связи и мемоизирует (кэширует) результат, чтобы исключить повторные вычисления при каждом открытии настроек.
*   **Сложность без кэша:** **O(L)**, где $L$ — заданная длина секретного числа (`length`).
*   **Сложность с кэшем (мемоизация):** **O(1)** (константное время).
*   **Обоснование:**
    1. При первом вызове рекурсивная функция делает строго $L$ шагов до базового случая (`l === 0`), уменьшая длину на единицу на каждом шаге. На каждом шаге выполняются простые математические действия за $O(1)$, что дает линейную сложность $O(L)$.
    2. При всех последующих (горячих) вызовах функция благодаря мемоизации проверяет наличие ключа в объекте `cache` через оператор `in`. Поиск в хэш-таблице (объекте) и возврат значения происходят мгновенно за константное время $O(1)$, вообще без запуска рекурсивных расчетов.

## Архитектура состояния и история попыток

В соответствии с ТЗ, состояние игры (`GameState`) спроектировано как единый иммутабельный объект. Обновление состояния реализовано через чистые функции, которые принимают текущее состояние и параметры, а возвращают новый объект состояния, созданный с помощью spread-оператора (`...`).

*   **История попыток:** Каждая новая попытка игрока добавляется в историю через создание нового массива (`[...history, entry]`) без использования мутирующего метода `.push()`. Это гарантирует сохранение истории состояний раунда и предотвращает случайные баги.
*   **Окончание игры:** При достижении условия победы (`bulls === length`), чистая функция `addGuessResult` автоматически переводит статус игры из `playing` в `won`.

## Принципы чистого кода (Clean Code)

*   **Принцип единственной ответственности (SRP / Single Responsibility):** Каждая функция решает строго одну задачу. Например, `createDigitValidator` только проверяет один символ на принадлежность к алфавиту, а `isValidGuess` собирает эти проверки вместе для валидации всей строки.
*   **Иммутабельность (Immutability):** Внутри `isValidGuess` исходные аргументы не мутируют. Использование методов `split` и `map` гарантирует создание новых массивов в памяти, сохраняя исходные данные в первозданном виде.
*   **Самодокументируемый код (Meaningful Names):** Имена функций и переменных явно отражают их намерения. Префикс `is` (например, `isValidGuess`, `isCorrectDigit`) четко указывает на возвращаемое булево значение.
